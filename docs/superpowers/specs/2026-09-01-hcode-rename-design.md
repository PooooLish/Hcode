# Hcode 彻底改名设计

## 背景

当前项目以 `MewCode` / `mewcode` / `mewcode-python` 标识品牌、Python 包、
命令行入口、项目目录、配置与会话目录。用户决定将项目彻底改名为 `Hcode`，
同时要求除名称及其必然对应的路径变化外，不改变任何现有功能。

本次重命名覆盖当前工作区项目及其专属运行环境，不访问或修改用户主目录中的
旧配置，不修改桌面原始压缩包，也不调用真实模型 API。

## 目标

- 品牌统一为 `Hcode`。
- 所有技术标识统一使用小写 `hcode`。
- 重命名后继续提供与当前项目相同的 Agent、TUI、远程模式、模型适配、工具、
  权限、上下文、记忆、MCP、Skill、Hook、子 Agent、Team 和 worktree 功能。
- 在新的独立 Conda 环境中通过与改名前相同的静态检查、CLI 冒烟和测试套件。
- 活跃项目中不再保留旧品牌、旧包名、旧 CLI 或旧配置目录引用。

## 非目标

- 不修复现有 P0/P1/P2 问题。
- 不重构模块、调整接口设计或改善代码风格。
- 不修改提示词语义、模型参数、默认 Provider、工具参数或权限规则。
- 不增加旧包名、旧 CLI 或旧配置目录的兼容层。
- 不迁移用户主目录中的旧配置、会话或记忆。
- 不删除旧 Conda 环境，不初始化 Git，不提交或发布项目。
- 不安装新的第三方依赖，不变更任何第三方依赖版本。

## 精确名称映射

| 当前标识 | 新标识 | 用途 |
| --- | --- | --- |
| `MewCode` | `Hcode` | 品牌及用户界面文案 |
| `MEWCODE` | `HCODE` | 全大写常量、标题或文档标识 |
| `mewcode` | `hcode` | Python 包、导入、CLI、路径和小写文案 |
| `mewcode-python` | `hcode` | 工作区项目名、环境名和历史项目标签 |
| `projects/mewcode-python` | `projects/hcode` | 工作区项目目录 |
| `mewcode/` | `hcode/` | Python 包目录 |
| `.mewcode/` | `.hcode/` | 项目配置、会话与运行状态目录 |
| `MEWCODE.md` | `HCODE.md` | 原项目说明文件 |
| `python -m mewcode` | `python -m hcode` | 模块启动命令 |
| `mewcode` console script | `hcode` console script | 安装后的 CLI |
| `.local/envs/mewcode-python` | `.local/envs/hcode` | 活跃 Conda 环境前缀 |

映射按长字符串优先、大小写精确的顺序执行，避免把组合名称替换成中间状态。
Python 类名、函数名和协议字段中不含品牌的部分保持不变。

## 变更范围

只读盘点发现，排除日志、输出、临时文件和缓存后，160 个文件包含旧名称；
旧名称还出现在三个路径名中：`.mewcode/`、`mewcode/` 和 `MEWCODE.md`。
重命名必须覆盖以下内容：

1. `pyproject.toml` 的发行包名、构建包路径和 console script。
2. 141 个源码文件中的绝对导入、模块运行入口、资源路径和用户界面文案。
3. 34 个测试文件中的导入、patch 目标、临时路径及名称断言。
4. `uv.lock` 中仅属于根项目的名称和 editable 包元数据；第三方版本和哈希不变。
5. 项目配置目录、示例路径、会话目录、记忆目录和运行状态路径。
6. `AGENTS.md`、`project.md`、README、分析报告、流程文档和环境说明。
7. 项目目录、包目录和原始说明文件名。

日志、输出、缓存和临时产物不作为代码迁移输入；改名后运行产生的新状态使用
新的 `.hcode` 路径。项目内现有 `.mewcode/config.yaml` 整体移动到 `.hcode/`，
不输出或复制其值到报告。桌面原始压缩包保持原样，文档改用“原始源码压缩包”
描述，不伪造其实际文件名。

## 功能等价约束

重命名前后，除名称和路径外，下列内容必须逐项等价：

- Python AST 的控制流、表达式和字面量仅允许品牌/路径字符串变化。
- 所有函数、方法和非品牌类名的签名保持不变。
- Provider 协议、端点、模型、API Key 环境变量名保持不变。
- 工具注册顺序、参数 schema、返回结构和错误语义保持不变。
- 权限模式、规则求值、路径沙箱和 OS 沙箱逻辑保持不变。
- TUI 布局、快捷键、命令处理和远程端口保持不变。
- 会话、记忆、压缩、文件历史、Hook、MCP、Skill、Team 与 worktree 行为保持不变。
- 测试数量与结果保持 `685 passed, 3 skipped`，除名称断言外不改变测试意图。

不通过测试来“接受”新的非名称行为；发现非名称差异时回滚该差异。

## 执行顺序与回滚

1. 在改名前使用现有环境运行 CLI 冒烟和完整测试，取得新鲜基线。
2. 完成项目规则要求的开源评估，记录本次不引入、不复制任何外部代码。
3. 在工作区 `runtime/rename-backups/` 下建立源码、测试、清单和文档的无密钥
   回滚副本及 SHA-256 清单；排除 `.mewcode/`、日志、输出、缓存和临时产物。
4. 机械替换文件内容中的名称，并通过替换清单限制变化种类。
5. 重命名包目录、项目配置目录和说明文件。
6. 更新交接文档和工作区项目标识。
7. 将项目目录移动到 `projects/hcode`。移动前解析并核对源、目标绝对路径，目标必须
   位于工作区 `projects/` 下且不存在。
8. 从已锁定的现有环境克隆 `.local/envs/hcode`，移除克隆环境中的旧 editable
   项目入口，并以 `--no-deps` 安装 `projects/hcode`；不访问网络、不改变依赖版本。
9. 使用新环境完成验证。旧项目环境保留，不删除，作为环境级回滚点。

项目没有独立 Git 仓库，因此不使用 Git diff 作为唯一回滚机制，也不擅自初始化
Git。若失败，先恢复目录名称，再从回滚副本恢复发生内容变化的文件；项目内配置
目录通过反向移动恢复，旧 Conda 环境始终保留可用。

## 验证

验证全部在无真实 API 调用条件下执行：

1. 对源码、测试、脚本和项目文档做大小写不敏感的旧名称扫描，结果为零。
2. 校验项目内不存在旧名称路径。
3. 对全部 Python 文件运行 `ast.parse`，语法错误为零。
4. 导入 `hcode` 及核心模块；确认导入 `mewcode` 失败，证明未保留兼容包。
5. 运行 `python -B -m hcode --help` 和安装后的 `hcode --help`，退出码均为零。
6. 解析 `.hcode/config.yaml` 并构造当前 DeepSeek 客户端，但不发送请求。
7. 在系统临时目录作为 `--basetemp` 运行完整 pytest，预期
   `685 passed, 3 skipped` 且无新告警。
8. 运行 `pip check`，确认新环境依赖一致。
9. 比较改名前后 Python AST 的规范化结构：忽略精确名称映射产生的字符串和导入
   路径差异后，其余结构必须一致。
10. 运行工作区 handoff/doctor，项目标识使用 `hcode` 且无待处理发现。

## 已知边界

- 用户主目录中如果存在旧配置、会话或记忆，新程序不会自动读取；这是彻底取消旧
  配置路径的直接结果。用户需要时可另行授权一次独立的数据迁移任务。
- 外部脚本若继续导入旧包或调用旧 CLI 将失效；本项目不提供兼容别名。
- 远程鉴权等现有安全风险原样保留，不在本次重命名中顺带修复。
- 根项目缺少许可证的既有风险保持不变，本次不发布或重新许可代码。

## 验收标准

- 活跃项目目录为 `projects/hcode`，包、CLI、配置目录和品牌均为 Hcode/hcode。
- 活跃项目中旧名称内容和路径扫描均为零。
- 新环境 `.local/envs/hcode` 可运行项目，旧环境仍存在且未被修改或删除。
- 完整测试仍为 `685 passed, 3 skipped`。
- 没有真实网络模型调用，没有保存、打印或迁移任何真实密钥。
- 源码差异仅由本设计中的精确名称映射产生。
